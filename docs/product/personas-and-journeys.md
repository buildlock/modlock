# Personas and user journeys

Status: research hypotheses; validate in Phase 0 interviews  
Last reviewed: 2026-09-01

## Player: casual customizer

Wants a cosmetic/audio change with one click and fears breaking the game or being banned. Needs plain provenance/risk, no jargon, automatic backup/rollback, and patch guidance.

Journey: discover → compare source/version/build → review install plan → close game → install → launch → patch warning/repair → remove/rollback.

## Player: power user

Uses many mods/profiles and edits CFG. Needs deterministic load order, conflict paths, variants, offline library, diffs, owned blocks, and diagnostics without Modlock overwriting manual work.

Journey: import/inventory → resolve unknowns → create profiles → order/conflicts → typed/raw config → switch/update/pin → export.

## Creator

Needs durable attribution, immutable versions, media/changelog/license, actionable scanner feedback, donations, and fair moderation/appeal.

Journey: verify/claim profile → draft → rights/metadata → quarantine upload → findings → publish → observe compatibility → update/deprecate/respond.

## Player/streamer whose setup is requested

Needs control over identity and exact values/items, no implied sponsorship, easy expiry/revocation, and no scraping.

Journey: identity verification → inspect exact artifact/version/public wording → approve → update/expire/revoke.

## Curator

Needs to assemble authorized references without reuploading other creators' binaries, select variants/order, explain purpose/conflicts, and handle unavailable items.

## Moderator/trust operator

Needs exact immutable evidence, policy codes, least privilege, emergency action, second review, consistent appeals, and separation of malware/legal/identity workflows.

These are hypotheses until interviews validate goals, vocabulary, failure anxiety, and willingness to use a separate utility.
